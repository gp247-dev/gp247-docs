# S-Cart のリリースとセキュリティ

## はじめに
このページは S-Cart（3.x 系）の**サイト運営者・管理者**向けです。各リリースの新機能、推奨バージョン、更新方法がわかります。
最新リリース: **S-Cart 3.12.0**（2026-11-26）。

## 推奨バージョン
`php artisan gp247:info`（または `composer show "gp247/*"`）を実行し、各行を **推奨最低バージョン** の列と比べます。

| パッケージ | 推奨最低バージョン | 最新 |
| --- | --- | --- |
| gp247/core | **3.16.0** | 3.19.0 |
| gp247/front | **3.11.0** | 3.15.0 |
| gp247/shop | **3.12.0** | 3.16.0 |
| gp247/mcp | **2.0.1** | 2.1.1 |

- 「推奨最低バージョン」**より低い** → [更新](#更新方法)をおすすめします。
- **達している** → S-Cart を再インストールしていなくても、重要な改善はすべて適用済みです。
- **サードパーティライブラリ** → あわせて `composer audit` を実行してください。[サードパーティライブラリ](#サードパーティライブラリ)を参照。

> ⚠️ **注意:** [更新方法](#更新方法)のコマンドで、**すべてのパッケージを同時に**更新してください。Composer が互いに合う
> バージョンを選びます（例：`gp247/shop` 3.16.0 には `gp247/core` 3.19 以上が必要）。サポート中の系列は
> [サポート期間](#サポート期間)をご覧ください。

## サポート期間
| 系列 | 基盤 | 状態 | セキュリティ修正の期限 |
| --- | --- | --- | --- |
| **3.x** | Laravel 13 · PHP 8.3 以上 | ✅ サポート中 | 2028 年 3 月 |
| 2.x 以前 | Laravel 12〜13 | ⛔ サポート終了 | — |

- **新機能** は最新の系列にのみ追加されます。
- **新しい系列が出たとき:** 前の系列は重大な不具合の修正をさらに 6 か月、セキュリティ修正を表の期限まで受けられます。期限は、
  その系列が使う Laravel のセキュリティサポート期限を超えません。
- **2.x 以前で稼働中のサイト:** 動作は続きますが、修正は提供されません。2.1 / 2.2 のサイトは
  `composer require … -W` と `php artisan gp247:update` で 3.x に移行できます — [3.x 系へのアップグレード](../install-upgrade/upgrade_ja.md) をご覧ください。

## 注目の新機能
- **私のデータ** — 顧客が自分のデータのコピーをダウンロードし、アカウントを削除できます。考え直す待機期間あり *(S-Cart 3.12)*
- **個人データ請求** — 顧客データの開示・削除の請求を 1 つの画面で、対応期限つきで処理 *(S-Cart 3.12)*
- **データ保存期間** — 設定した日数を過ぎた古いデータを自動で整理。cron 不要 *(S-Cart 3.12)*
- **都道府県・市区町村をリストから選択** — 住所プラグインで検索して選択、郵便番号から検索 *(S-Cart 3.12)*

## 更新方法
**手順 1 —** データベースとサイトのフォルダーをバックアップします。

**手順 2 —** コードを更新します。
```bash
composer update gp247/core gp247/front gp247/shop gp247/mcp
```
S-Cart 3.5.0 より前にインストールしたサイトにはまだ MCP サーバーがありません。上のコマンドの代わりに `composer require gp247/mcp -W` を 1 回実行してください。

**手順 3 —** データ・設定・キャッシュの更新を適用します。
```bash
php artisan gp247:update
```

**手順 4 —** `php artisan gp247:info` でバージョンを再確認します。

リリースによっては追加の対応が必要です。下記の各リリースの **📋 更新時の対応** をご覧ください。
詳しい手順は [GP247 と S-Cart の更新](../install-upgrade/update_ja.md)をご覧ください。

### S-Cart 3.12.0 — 2026-11-26
**顧客が自分のデータをダウンロード・削除でき、住所はリストから選べます。**

**✨ 新機能**
- **私のデータ** — 顧客が自分のデータのコピー（ZIP ファイル）をダウンロードし、アカウントを削除できます。考え直す待機期間あり
  （[ドキュメント](../s-cart/personal-data/personal-data_ja.md)）
- **個人データ請求** — 顧客データの開示・削除の請求を 1 つの画面で処理。アカウントのないお客様も `/privacy-request` ページから
  請求でき、期限切れは警告されます
- **顧客の削除ですべて削除** — 個人データをあらゆる場所から削除し、注文は名前・連絡先を除いて帳簿用に残ります。古いバックアップを
  復元しても削除した顧客は戻りません
- **データ保存期間** — 放置されたカート、お問い合わせ、古いログを設定した日数で自動整理。cron 不要
- **都道府県・市区町村をリストから選択** — 国別の住所プラグインで、顧客が検索して選択、郵便番号からも検索
  （[ドキュメント](../s-cart/customer-address/customer-address_ja.md)）
- **開発者向け:** 顧客データを持つテーブルをプラグインが宣言し、エクスポート・削除・期限での整理の対象に
  （[ドキュメント](../extension/declare-personal-data_ja.md)）。国別の住所プラグイン
  （[ドキュメント](../extension/create-address-plugin_ja.md)）。`gp247:personal-data-retention` コマンド

**🔧 改善:** バックアップに、以前の復元が残したテーブルのコピーが含まれなくなりました。フォルダーがなくなったプラグイン・
テンプレートは **登録解除** ボタンで外し、新規として再インストールできます。`laravel/legacy-factories` の放棄警告が出なくなりました

**📋 更新時の対応**
- `composer update` の後に `php artisan gp247:update` を実行（個人データ請求と保存期間のテーブルを作成、顧客の最終ログイン列を追加）
- **セキュリティ › データ保存期間** を確認: 既定で有効な項目（管理操作ログ 365 日、カート 180 日など）は 30 日後に整理を始めます。
  長く残したい場合は、それまでに日数を変えるか無効にしてください
- 管理画面の顧客の **削除** ボタンは削除請求を作成し、3 日待ってから削除します（取り消し可能。日数は **サイト設定 › 個人データ** で変更）
- フッターまたはプライバシーポリシーから `/privacy-request` ページにリンクしてください（ページはメール送信が有効なときだけ存在します）
- *（独自テンプレート）* マイページに **私のデータ** を追加 — 標準テーマと GP247-EC 1.0.7 以降は対応済み
- *（Laravel 7 形式の `factory()` を使うサイトのコード）* `composer require laravel/legacy-factories` を実行

### S-Cart 3.11.0 — 2026-11-23
**複製は元の SEO を引き継がず、新規インストールは S-Cart の名前とロゴ入り。**

**✨ 新機能**
- **複製で SEO をコピーしない** — 商品・ページの複製は SEO タブが空から始まり、元と同じタイトルで Google に出ません
  （[ドキュメント](../s-cart/product/product-duplicate_ja.md)）
- **新規インストールに S-Cart の名前とロゴ** — ストア名、管理画面、あいさつ文、メニューを S-Cart 向けに設定。稼働中のサイトは変わりません
- **カスタム設定に保存ボタン** — 複数行を編集してから 1 回で保存。ほかの設定タブと同じ操作
- **フッターに Facebook グループ** — 標準テーマで Facebook の隣に Facebook グループのアイコン
- **開発者向け:** SEO プラグイン用の接続点（SEO チェックのコンテンツ取得元、追加 JSON-LD、プラグインの 301）。core・front・shop・mcp の
  公開テストスイートと CI、共通のテストヘルパー。GP247 上の製品はインストール時に名前とロゴを指定可能

**🔧 改善:** 独自の説明がないページにストアの説明を繰り返さなくなりました。SEO チェックが MariaDB で動作するようになりました。
エラーページへのリダイレクト項目は、直近 7 日間に 404 を返した転送先だけを表示するようになりました

**📋 更新時の対応**
- `composer update` のあと `php artisan gp247:update` を実行（Facebook のリンクのキーを `group_url` に変更。設定済みのリンクは保持）
- *（独自テンプレート）* Facebook のリンクが `fanpage_url` を読んでいる場合は `group_url` を読み、`fanpage_url` を予備として残してください
- *（ニュースプラグインを使うサイト）* 記事を複製するには News を 3.2.0 以上に更新してください

### S-Cart 3.10.0 — 2026-11-20
**GA4・Meta ピクセルは ID を貼るだけ、Cookie バナー付き。商品はボタン 1 つで複製。**

**✨ 新機能**
- **GA4・GTM・Meta ピクセルの計測コード** — ID を貼るだけ。お客様が許可した Cookie グループのコードだけが動作
  （[ドキュメント](../seo/tracking-and-cookies_ja.md)）
- **Cookie バナー** — 事前に同意を求める・お知らせのみ・オフから選択。お客様は「Cookie 設定」からいつでも変更可能
- **GA4 と Meta で広告からの売上を把握** — 商品閲覧、カート追加、購入手続き、購入のイベントを自動送信
- **セキュリティヘッダー** — ヘッダーごとのオン / オフ、HSTS の段階的な有効化を管理画面で
  （[ドキュメント](../security/security-production-config_ja.md#セキュリティヘッダー)）
- **商品とページの複製** — ボタン 1 つで非公開の複製を作成し、違う部分だけを修正
  （[ドキュメント](../s-cart/product/product-duplicate_ja.md)）
- **商品名で商品を検索** — 管理画面の商品一覧で。カテゴリーの絞り込みに検索ボックス
- **開発者向け:** テンプレートは CSS 変数でバナーの色を変更可能。データ移行プラグインは他プラットフォームの旧 URL からの 301 を登録可能。
  商品の複製時にプラグインが独自データをコピー可能（[ドキュメント](../seo/seo-for-developers_ja.md)）

**🔧 改善:** データの多いサイトで商品・顧客・注文を保存してもキー重複のエラーが出なくなりました。該当ページのない URL（404 ログから
取ったものなど）にも 301 リダイレクトが効くようになりました。大規模ストアのカテゴリーページが速く開くようになりました

**📋 更新時の対応**
- `composer update` のあと `php artisan gp247:update` を実行（商品とカテゴリーの対応表にインデックスを追加。非常に大きなストアでは
  ピーク時間外にコマンドラインから実行）
- 更新後、サイトは 4 つのセキュリティヘッダーを送信します。別ドメインに埋め込む（iframe）必要があるサイトは、**セキュリティヘッダー**
  画面で X-Frame-Options をオフにしてください
- 計測コードと Cookie バナーは **初期状態でオフ** です。使うときは **SEO › トラッキングコードとCookie** を開いてください（管理者のみ）
- *（Docker で運用）* ヘッダーが 2 回送られないよう、S-Cart の新しい `docker/nginx/default.conf` を取り込んでください。このファイルを
  編集している場合は変更をマージしてください
- *（独自テンプレート）* 計測コードと Cookie バナーを使うため、`<head>` 内の `<x-gp247-front::meta-head>` を残してください

## セキュリティ

サイトを安全に保つには、更新だけでは足りません。設定、暗号化キー、バックアップ、アカウント、インシデント対応については [GP247 システムのセキュリティ](../security/security-introduction_ja.md) を参照してください。

GP247 は定期的にセキュリティを見直し、改善を各リリースに含めています。サイトを安全に保ついちばん簡単な方法は、
[推奨バージョン](#推奨バージョン)以上を使い、新しいリリースが出たら更新することです。

## サーバーソフトウェア（PHP・Web サーバー）
PHP と Web サーバーの不具合は GP247 のリリースではなく各提供元が修正します。こちらも最新の状態に保ってください。

| 問題 | 深刻度 | 修正済みの PHP |
| --- | --- | --- |
| **PHP2Shell** — リモートコード実行（CVE-2026-109618、CVE-2026-109619）· 2026-10-21 | 緊急 | 8.3.36 · 8.4.27 · 8.5.12 |

**対応方法**
- **PHP バージョンの確認:** `php -v`、または **管理画面 → サーバー情報**。
- **公式リリースの PHP**（php.net、公式 Docker イメージ、バージョンを選べる多くのコントロールパネル）: 使用中のブランチの
  修正済みバージョン以降に更新します。
- **Linux ディストリビューション（Ubuntu、Debian、RHEL など）やホスティング事業者が管理する PHP:** 古いバージョン番号のまま
  修正が適用されることが多く、**バージョン番号だけでは安全かどうか判断できません** — OS の最新アップデートを適用するか、
  CVE-2026-109618 と CVE-2026-109619 が修正済みか事業者に確認してください。
- **すぐに更新できない場合:** `php.ini` で `session.upload_progress.enabled = Off` を設定し（GP247 はこの機能を使いません）、
  PHP を再起動します。リスクは下がりますが、更新の代わりにはなりません。
- **Docker で運用している場合:** [DOCKER.md](https://github.com/gp247-official/s-cart/blob/master/DOCKER.md) の「Security updates」に
  従ってください。

## サードパーティライブラリ
GP247 が使うライブラリ（Livewire、Symfony など）の不具合は各ライブラリの提供元が修正します。必要に応じて GP247 は最低バージョンを引き上げます。
下の 2 件で影響を受ける機能は GP247 のコードでは使っていませんが、サードパーティのプラグインが使う場合があります。更新をおすすめします。

| 問題 | 深刻度 | 修正済みのバージョン |
| --- | --- | --- |
| **Livewire** — 権限チェックの回避（GHSA-mhf7-xp6r-6qrc） | 中 | livewire/livewire 4.4.8（core 3.10.2 で必須） |
| **symfony/mime** — メールヘッダーインジェクション（CVE-2026-45070） | 中 | symfony/mime 7.4.22 |

**対応方法**
- **更新:** `composer update` を実行し、`composer show livewire/livewire symfony/mime` で確認します。
- **すべてのライブラリをまとめて確認:** `composer audit` で、公開済みの問題があるライブラリを一覧できます。
